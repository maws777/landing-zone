## The project
 
A single coherent project on AWS showing I can build a secure multi-account cloud platform and run a real workload on it:
 
1. **Landing zone**: AWS Organizations with OUs, separate accounts per purpose, Service Control Policies, IAM Identity Center for human access, GitHub Actions deploying through OIDC (no long-lived keys anywhere).
2. **A production-style app**: a remote **calorie-tracking MCP server** I use daily from Claude (Claude Code / desktop / claude.ai as a custom connector). Decided 2026-10-16, see roadmap step 8 for the full design. In short: Claude estimates nutrition itself (from text or a photo) and calls tools with structured values; the server validates and stores, with no food database. Always-on serverless core: API Gateway HTTP API → Lambda (MCP server) → DynamoDB, Cognito as the OAuth authorization server, ~€1/month. A read-only dashboard website (S3 + CloudFront, installed on my iPhone as a home-screen PWA) showing the day's table, targets, trends, leftovers and an AI summary with tips written by a small Claude model on Bedrock (the one deliberate AI call in the app), with "memory" built from computed stats plus its own diary notes. Meal-prep batches (cook 6 portions, eat them over the week). The ECS Fargate + ALB + WAF stack running the same container image is an **optional stretch goal**, decided at the end. The threat model stays real: public HTTPS endpoint with OAuth token validation, tenant isolation (user ID from the token, never from tool arguments), stored prompt injection reaching the summary model, stored XSS on the dashboard, cost abuse of the Bedrock-backed endpoint, rate limiting, and diet data as potential GDPR Article 9 health data.
3. **Security guardrails**: preventive controls (SCPs) plus detective controls: organization CloudTrail → EventBridge → Lambda that detects and auto-reverts risky changes (public S3 bucket, security group open to 0.0.0.0/0 on SSH/RDP, overly broad IAM grants) and alerts me. A Sandbox OU with relaxed SCPs exists specifically so the detective side can be demoed.
4. **Observability and docs**: dashboards, alarms, an SLO, a load test, a README with an architecture diagram, decision records (ADRs), a threat model and a cost breakdown.
